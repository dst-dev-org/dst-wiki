## 审阅得到的关键边界

- efficientuser 挂执行者，不主动消费；finiteuses 有动作消费映射才读取，之后还会经过物品消费修正回调。Weapon OnAttack 另读 ATTACK 倍率后直接 Use，不经过该动作修正回调；普通直接 Use 不自动读取倍率。
- “使用效率”不等于固定省耐久语义：耐久路径乘消费量，HEAL 路径乘施用者的基础治疗贡献。范围由消费者决定，没有全动作统一折扣。
- 来源列表默认乘算，同源同 key 覆盖，实体删除可自动撤销，卸装／效果失效仍需主动撤销。efficientuser 的 MINE 映射没有传 key，添加副动作会覆盖默认槽，按 key 撤主动作时副动作却整源删除；文档建议分离来源，未改游戏实现。
- worker 只维护自身动作基础量；DoToolWork 优先 invobject.tool，其次 doer.worker，最后 1。返回 0 是 Lua 真值，不回退；SetAction(nil 第二参数) 写默认 1，0 不等于删除能力。
- Woodie 的 worker 在变海狸时添加、退出移除，构造后还写动作量，普通角色 PrefabPostInit 不能覆盖之后才出现的组件。示例在 ComponentPostInit 包装 GetEffectiveness，保留原版随后写入的技能基础量；读档由 OnPreLoad 恢复形态。此例复用宿主，不承诺任意角色加组件即可徒手工作。
- workmultiplier 只叠加工作量；没有 key 隔离或 MINE 副动作映射。DoToolWork 依次算基础量乘人物倍率、目标反弹、特殊工作量、目标内部修正与扣量。特殊回调返回工作量本身；nil／false 回退，0 保留。固定正返回值可能绕过反弹后的零量边界。
- Wolfgang 的特殊回调有条件、随机与声音副作用；普通加成不覆盖它。mightiness 同时设置工作量与使用倍率，恰好说明两条链独立；不声称工作量加倍必然让总时间／总耐久恰好减半。
- 三个组件都不保存本身配置；来源恢复由角色／效果系统负责。efficientuser 有移除时 Reset，workmultiplier 没有相同钩子，不能复制生命周期结论。示例永久来源由玩家初始化重施，临时效果的撤销方式另作说明。
