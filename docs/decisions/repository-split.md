| 仓库 | 职责与主要内容 |
|---|---|
| dst-mod-dev-skill | 模组开发、代码修改／排查、方案查询与模组自身 LLM Wiki 维护；原 dst-mod-wiki-skill 改名。仓库根提供可安装的 SKILL.md、开发规则、最小查询与源码准备。 |
| dst-wiki-skill | 共享知识的独立查询、机制页／通用 cookbook 增修、审校及知识导航维护；规则、格式、模板与必要辅助脚本随 Skill 分发。 |

查询共享骨架并整合进模组、开发时查机制／源码归开发 Skill；增修共享骨架归知识库 Skill。模组自身的约定、实现、问题与测试记录留目标模组，不集中到 Skill 仓。普通开发只需开发 Skill＋知识资产；维护共享知识只需知识库 Skill＋知识资产。两个 Skill 彼此不作为必装前置。

W03／W04 工程验收报告跟随工具箱，W05 的检索工具报告同样归工具箱；组件／骨架／真实任务检视、覆盖清单与剩余组件盘点留知识仓。历史报告正文、历史命令与 wiki/log 原前缀不改，迁移映射在本决策和验收说明；现代入口链接迁移后的文件。

## 安装与路径

每个 Skill 仓根是完整 Skill 目录，可整体复制到 harness 支持的 skill 目录；不依赖目录名、.claude／.codex 层级或另一个 Skill。宿主专属入口仅作触发适配，核心操作规则保持通用。

用户可自由选择知识仓位置。第一版配置在用户主目录 `.dst-wiki/config.json`，包含绝对 `knowledge_root`，按需增加 `toolbox_root`。本次明确路径优先于用户配置；缺配置时一次确认位置，不扫描整个磁盘、不自动下载、不把路径写入安装后的 SKILL.md。项目级覆盖配置留实际需求，不在首版增加。配置不是 harness 内建功能，由 Skill 指导 AI 读取，PowerShell 解析器无需 Python；同会话复用有效结果。

知识仓内部保持 `wiki/` 与 `raw/current/{scripts/,BUILD.txt}` 同级布局，维持已有源码相对证据链接；输出统一 `output/`。目标模组依当前任务／项目入口定位，不在用户全局配置里固定。源码准备接受显式 KnowledgeRoot，不从脚本安装位置推导知识路径；检查版本、更新先校验、保留旧快照、失败回滚继续保留。

无需 Python 的配置／源码准备脚本随两个独立 Skill 分发；实现只在 dst-wiki-skill 维护，开发 Skill 携带生成副本并标明来源／同步方式。安装后的副本不能跳转另一 Skill。最小查询规则按各自职责分别维护，改动时交叉检查共同证据、版本、懒加载和兜底约束。共享 Wiki 本身只维护一份。

工具箱使用显式 `--knowledge-root`、`--source-root`、`--wiki-root`、`--output` 等输入，不假定四仓同级或安装在开发工作区。页面／导航校验通过 `--format` 指定知识库 Skill 的权威 write-format；工具不复制生产格式规则。工具是可选增强，缺 Python、Rust、LuaLS、fork 或缓存时仍可用 Markdown 和定向源码。

## AST 与远程内容

Full Moon AST 是解析内部结构，默认不落盘。精简 facts、source-index、知识缓存和报告放知识仓本地 output，可重建，Git 忽略；源码变化或生产者／契约不匹配须复查，不因版本号相同认定有效。提取成本低，第一版不推送全量 AST／facts／索引包。

提交提取器、Schema、固定版本配置、必要测试样本、核验后的 Wiki／导航。游戏源码／资源、raw 历史快照、构建产物、个人配置和完整 fork 克隆不提交。正式 reviews 与注解仍在现有 lsp-dst fork，它是四仓之外的独立依赖；固定 pin 跟随工具箱且不在克隆内。

## 迁移验收与限制

保持 Wiki 知识页与导航原字节、游戏源码、正式 fork 输入、机器契约及原字节 fixtures；日志只追加。先解耦路径再验证异地安装、含空格路径、明确参数优先、源码缺失、无工具箱／Python的基础查询与维护规则，运行对应工具回归。

目录复制／路径与脚本检查只能证明文件及命令层面的可移植性。不同 harness 的真实自主路由与外部目录权限另行验收；没有实际运行就不宣称已全面兼容。分仓不证明 token 收益，也不执行游戏场景测试。
